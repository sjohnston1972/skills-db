SCORING SYSTEM:
- Level 0: No Exposure (not counted)
- Level 1: Training only
- Level 2: Shadowed or Lab Deployed
- Level 3: Implemented once
- Level 4: Implemented multiple times
- Level 5: Subject matter expert

AGGREGATION LOGIC:
Main Skill Score = AVERAGE(all sub-skill scores in that category)
- Automatically recalculates when sub-skills change
- Rounded to nearest integer (1-5)
- Used in radar charts and heatmap

EXAMPLE:
Main Category: "Cisco Enterprise and SD-WAN"
Sub-Skills:
  - Cisco Switching: 5
  - Meraki Switching: 4
  - Cisco Wireless: 4
  - Meraki Wireless: 3
Main Skill Score: 4 (average of 5,4,4,3 = 4.0)

================================================================================
AUTHENTICATION SYSTEM DETAILS (NEW v4.0)
================================================================================

SECURITY IMPLEMENTATION:
- SHA-256 password hashing using Web Crypto API
- No plaintext passwords stored
- Session-based authentication (sessionStorage)
- Role-based access control (Admin vs Resource)

USER ROLES:

1. ADMIN ACCESS:
   - Full access to all features
   - Can view and edit all engineers
   - Can manage all skills and categories
   - Can add/delete engineers and skills
   - First-time setup: creates admin password on first login attempt
   - Password stored as SHA-256 hash in localStorage

2. RESOURCE ACCESS:
   - Limited to viewing own profile
   - Can edit own skills only
   - Cannot access other engineers' data
   - Cannot add/delete engineers or skills
   - Optional: Resources can have passwords set during creation
   - If no password set, that resource cannot log in

LOGIN FLOWS:

Resource Login:
1. Enter email address
2. Enter password (if set)
3. System finds engineer by email
4. Validates password hash
5. Creates session with resource role
6. Redirects to own profile

Admin Login:
1. Enter admin password
2. First time: Sets admin password
3. Subsequent: Validates against stored hash
4. Creates session with admin role
5. Full access to all features

SESSION MANAGEMENT:
- Sessions stored in sessionStorage (cleared on tab/browser close)
- Session contains: user ID, role, name, email
- Session checked on page load to restore login state
- Logout clears session and redirects to dashboard

KNOWN LIMITATIONS & NOTES

1. DATA PERSISTENCE:
   - Uses browser localStorage only
   - Data is per-browser, per-device
   - No server-side database
   - Clearing browser data will reset (includes passwords!)
   - Use export function for backups

2. AUTHENTICATION (v4.0):
   - Client-side only (no server validation)
   - Sessions cleared on browser/tab close
   - Passwords stored as hashes in localStorage
   - No password recovery mechanism
   - No password strength requirements enforced
   - Admin password is device-specific (localStorage)
   - No centralized user management
   - Security relies on browser localStorage protection

3. MULTI-USER:
   - Not designed for concurrent editing
   - Basic authentication implemented (v4.0)
   - No conflict resolution
   - No real-time synchronization
   - Best for single-user or controlled team access
   - Resource users can only view/edit own profiles

4. SKILL WEIGHTING (v4.0):
   - Weight field added but not yet used in calculations
   - Skill types field added but not fully implemented
   - Future: Use weights for prioritized gap analysis
   - Future: Filter/group by skill types

5. EXCEL FILE:
   - "Data" tab was skipped (different structure)
   - Initial data extraction is one-time
   - Future Excel updates require manual import or re-extraction

6. BROWSER COMPATIBILITY:
   - Requires localStorage support
   - Won't work in private/incognito mode (data won't persist)
   - Modern browsers only (ES6 JavaScript)
